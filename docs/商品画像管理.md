# LUNA 商品画像管理

## 既存データの保全

- 既存画像は上書き、移動、削除しない。商品・ユーザー・注文の初期化は行わない。
- 商品画像の表示処理ではデータベースを更新しない。過去の注文の画像パスも保持する。
- フロント画面の構成、CSS、表示サイズは維持する。管理画面には既存のスタイルでアップロード操作を追加する。
- データベースへの接続情報が未設定のため、画像台帳の関連商品は未確認とする。ファイル数を商品数と解釈しない。

## 表示仕様

- 主画像は 3:4、標準サイズは 900×1200 とする。既存画像には遡及して適用しない。
- アイボリー・薄灰色の背景、自然光、余白を基本とし、商品の色・形・素材感を明確にする。
- 展示用 WebP は 150～400 KB を目安とし、原本を別途保管する。
- 正方形・横長の既存画像を加工する場合は別名で保存する。機械的な中央切り抜きや引き伸ばしは避ける。
- 画像未設定・参照先不在・読み込み失敗時は `/images/common/no-image.svg` を表示する。
- 商品管理で画像欄を空欄にすると共通画像を使用する。入力済みの不正なパスはエラーとする。
- SVG は共通画像のみ許可する。商品画像は PNG・JPEG・WebP を使用する。

## 命名規則

新規画像: `luna-{asset-id}-{type}-{color}-{view}-v{version}.{ext}`

例: `luna-a0001-knit-ivory-front-v01.webp`

- 小文字英数字とハイフンを使用する。台帳の資産番号は一意で変更しない。
- type: `knit`, `cardigan`, `coat`, `skirt`, `bag`, `accessory` など。
- view: `front`, `back`, `detail`, `style`。変更時は版番号を上げ、別ファイルとする。
- 既存の `knit1.png` などは互換性のため維持する。

## 台帳と確認

`product-image-inventory.csv` に既存画像の寸法、内容、SHA-256 と確認事項を記録する。
関連商品の確認には、別途読み取り専用で取得した商品と注文明細の画像パス一覧を用いる。
画像を使っていないように見えても、注文履歴からの参照を確認するまでは削除しない。

読み取り専用の資産確認:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/audit-product-images.ps1
```

データベースから別途エクスポートした CSV を照合する場合は、`id,name,image_url` 列を用意する。
このスクリプトは DB に接続せず、ファイルの変更も行わない。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/audit-product-images.ps1 -ProductCsv C:\temp\products.csv
```

## AI 画像の一括受け入れ手順

1. `image-import-template.csv` をコピーし、商品名、種類、色、原本、公開先、出所を記載する。
2. 原本は公開ディレクトリの外で保管する。画像の生成だけで商品を追加しない。
3. ファイル名、実際の形式、3:4 比率、寸法、サイズ、ハッシュ重複を検査する。
4. 商品名・分類・色・柄・形状と画像を目視確認する。同じ商品の複数画像でもデザインの一致を確認する。
5. 確認者が承認した画像のみ、未使用のファイル名で `static/images/products/` に追加する。
6. 配置後、既存の商品編集機能で対象商品の画像を関連付ける。データ更新はこの明示的な保存時に限る。
7. 公開画面と管理画面で表示を確認し、台帳を更新する。

同じ商品の各画面での共用は認める。異なる商品への流用や色違いの代用は認めない。
メンズ・アクセサリーなど既存画像で対応できない商品は、適切な画像が揃うまで NO IMAGE とする。
管理画面は単一画像のアップロード・プレビュー・確認に対応する。保存先と手順は `商品图片上传.md` を参照する。
一括登録・自動生成・自動公開は実装対象外とする。アップロード画像は UUID の名前で保存し、台帳の命名例は手動準備画像に適用する。

## 既知の確認事項

- `coat1.png` は女性モデルの着用画像だが、例示 SQL はメンズに分類している。実データと商品仕様の確認が必要。
- アクセサリーカテゴリで使用していたカーディガン画像は共通画像に差し替える。カテゴリの位置とリンクは維持する。
- 既存画像は 1:1 または 4:3 で約 1.9～2.5 MB。軽量版の作成は原本と DB の照合後に行う。

## 検証

画像サービスの単体テストはデータベースに接続しない。
画面・業務テストは既存の test プロファイルの H2 メモリ DB のみを使用する。
MySQL の初期化や SQL スクリプトの自動実行は行わない。
