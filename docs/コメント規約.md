# LUNA コメント規約

Java、HTML、CSS、JavaScript、SQL、設定、テスト、運用スクリプトのコメントを対象とする。

- コメントは自然な日本語で記述し、UTF-8 で保存する。
- 処理を逐語訳せず、業務上の理由、制約、例外、互換性の意図を説明する。
- 「〜する。」「〜を保持する。」などの常体を基本とする。
- 商品画像、在庫、入荷、注文、支払い、返金などの用語を統一する。
- 公開 API や判断が難しい業務処理には、必要に応じて Javadoc を付ける。
- TODO には未対応内容と解決条件を明記する。不要なコメントやコードの残骸は残さない。
- 実装変更時にコメントも確認し、実際の動作と一致させる。
- クラス名、変数名、URL、外部 API 名、CSV の機械可読列名は英語のままとする。
- Maven Wrapper など外部由来のファイルは、更新互換性のため機械的に翻訳しない。

例:

```java
// 注文履歴から参照されるため、既存の画像ファイルは削除しない。
```

利用者向け README や説明文の言語は、ソースコードのコメント規約とは別に扱う。
