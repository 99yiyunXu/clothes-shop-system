# 商品图片上传（第三阶段）

## 存储与兼容

- 默认保存目录：`${user.dir}/data/product-images`。在项目根目录运行时为 `D:/Eclipse/clothes-shop-system/data/product-images`。
- 建议在 Eclipse Run Configurations → Environment 中固定 `LUNA_IMAGE_DIR=D:/Eclipse/clothes-shop-system/data/product-images`。之后的重启和部署继续使用同一目录，不要设到 target、临时目录或编译输出中。
- 目录在第一次成功上传时创建。Maven clean 和重新构建只处理 target，不会清除此目录。目录内容不提交到 Git，需与 MySQL 一起单独备份。
- 配置 `shop.images.max-files` 可调整目录文件数上限，默认2000。该容量检查按单应用实例执行；多实例部署前需统一存储及配额管理。
- 原静态图片不改名、不移动、不覆盖。`products.image_url` 仍然是图片路径，不存图片二进制；不需要数据库迁移。
- 新图使用32位 UUID 文件名，经 `/images/uploads/{filename}` 访问；不公开目录列表、临时文件或任意磁盘路径。
- 图片为空、磁盘文件不存在或浏览器加载失败时，继续使用现有 NO IMAGE 处理。
- 只读图片核对工具会按 `LUNA_IMAGE_DIR` 或默认项目目录核对导出 CSV 中的上传图片，也可用 `-UploadDirectory` 指定实际保存目录。

## 上传、预览、确认、保存

1. 重新启动应用，使用已有管理员账号打开 `/admin/products/new` 或 `/admin/products/{id}/edit`。
2. 原“画像パス”可以继续手动填写。上传时选择 JPG、PNG 或 WebP，点击“アップロードして確認”。
3. 上传成功后显示服务器保存的图片预览，原商品图片路径暂不变化。
4. 检查图片与商品名称、颜色和类型是否对应，点击“この画像を使用する”，把新路径填入图片栏。
5. 点击页面底部的“商品を登録する”或“変更を保存する”，才更新商品数据。
6. 不使用时点击“選択を取り消す”。新图不会关联到商品，原图片保持不变。

有图片待上传、上传中或待确认时，会阻止误提交商品表单。上传失败会显示错误，商品不自动保存。选择取消后仍可继续使用原路径保存。

## 校验与限制

- 一次只允许1张，上传源文件最大5 MiB，请求整体最大6 MiB。
- 每个登录会话最多成功上传20张，重新登录后会话计数重置；目录容量上限仍继续生效。
- 扩展名、声明的 MIME、解码器识别的实际内容必须一致；拒绝伪装图片、SVG、损坏图片、空文件和多文件请求。
- 单边最多6000像素，总像素最多1200万；只接收静止图。推荐3:4，不强行裁切原图。
- 实际解码后重新编码，JPEG保存为JPG，PNG和WebP保存为PNG，移除原文件的附加数据和元数据。转换后的文件最大16 MiB。
- WebP 解码使用 [TwelveMonkeys ImageIO](https://github.com/haraldk/TwelveMonkeys/releases/tag/twelvemonkeys-3.15.0)；服务端不依赖操作系统的 WebP 插件。
- 用临时文件写完后发布唯一文件，不覆盖已有文件；失败时清理本次临时文件。
- 上传沿用 `/admin/**` 管理员权限和原有 CSRF 检查，没有修改安全认证配置。图片读取沿用 `/images/**` 公开访问范围，并返回明确 MIME 与 nosniff。

## 失败与文件保留

上传接口没有商品写入操作。上传失败、商品验证失败或过期版本保存失败均不会修改原商品或删除原图片。

上传成功但未确认、放弃编辑、商品保存失败时，新文件暂时保留，计入容量上限，不自动删除。这样避免误删其他商品或历史订单已引用的图片。后续若清理，必须先核对商品和注文明细引用并备份；本阶段不提供删除和自动清理功能。

## 测试方式

```powershell
.\mvnw.cmd -B -ntp test
node --test tools/product-images.test.cjs tools/admin-image-upload.test.cjs
```

上传测试用独立 H2 内存数据库和 JUnit 临时目录；测试不会上传到实际持久化目录，也不会写入 MySQL。覆盖格式解码、预览后确认关联、同名文件不覆盖、无权限与缺少 CSRF、文件过大、损坏及伪装内容、数量限制、磁盘/读取失败、商品保存失败、图片读取及服务重建后的文件保留。

本次执行结果：37项 Java 测试全部通过，4项 JavaScript 测试全部通过；原有12张图片的哈希校验全部一致。未在连接实际 MySQL 的运行实例中进行写入式验收。

## 浏览器验收

- 使用测试商品上传三种格式，确认预览后保存，再刷新前台确认图片显示。
- 上传后先不确认，检查原图片路径不变；取消后原商品图片仍可访问。
- 提交伪装图片或大于5 MiB文件，确认报错且商品资料未被保存。
- 依次上传同名文件，确认获得不同 UUID 路径。
- 重启 Eclipse 应用并重新构建，确认已上传图片仍可访问。保持 LUNA_IMAGE_DIR 和磁盘内容不变。
- 普通用户无法调用上传接口；空图片仍正常显示 NO IMAGE。

本阶段不涉及批量导入、补货、虚拟钱包、订单、购物车、支付、库存扣减或前台页面样式。
